Código aplicado

Los temas vistos en clase (DOM, Eventos, DOM Traversing, Event loop, Promesas, Async/Await), explicados sobre el código real de esta app.

La misma arquitectura en los dos lados del curso

Igual que en el backend en Java (Dominio → Servicio → Repositorio, arquitectura hexagonal), el frontend separa sus capas en archivos distintos: repositorios.js guarda los datos en memoria, servicio.js aplica las reglas de negocio (agendar, cancelar, registrar...) y cada pantalla solo le pide cosas a servicioSalud, sin tocar los datos directamente.

Semana 9 · DOM

Construir la interfaz desde JavaScript

Al cambiar de especialidad no se recarga nada: la lista de médicos se reconstruye leyendo un arreglo y reescribiendo el DOM con innerHTML.

function dibujarMedicos() {
  const especialidad = document.getElementById("agendar-especialidad").value;
  const filtrados = medicos.filter(m => m.especialidad === especialidad);

  document.getElementById("lista-medicos").innerHTML = filtrados.map(m => `
    <button data-medico="${m.id}">
      <strong>${m.nombre}</strong>
    </button>`).join("");
}

Semana 10 · Eventos y EventListener

Separar el comportamiento del HTML

Ningún botón usa onclick en el HTML. Cada interacción se conecta desde JS con addEventListener.

botonesAuthTab.forEach((boton, indice) => {
  boton.addEventListener("click", () => {
    botonesAuthTab.forEach(b => b.classList.remove("active"));
    boton.classList.add("active");
    indicadorTab.style.transform = `translateX(${indice * 100}%)`;
  });
});

Semana 11 · DOM Traversing

Delegar el evento y recorrer el DOM

Las tarjetas de médicos se crean dinámicamente, así que un solo listener vive en el contenedor. closest() sube por el árbol del DOM hasta encontrar la tarjeta completa.

document.getElementById("lista-medicos").addEventListener("click", async (e) => {
  const tarjeta = e.target.closest("[data-medico]");
  // si el clic no ocurrió dentro de una tarjeta, se ignora
  if (!tarjeta) return;

  medicoSeleccionado = medicos.find(m => m.id === tarjeta.dataset.medico);
  // (...continúa pintando la agenda de ese médico)
});

Semana 13 · Event loop y Callbacks

Tareas que se repiten sin bloquear la app

setInterval programa un callback que el event loop ejecuta cada 550ms. Mientras tanto la página sigue respondiendo a otros clics.

const intervalo = setInterval(() => {
  rellenoBarra.style.width = pasosProgreso[paso].hasta + "%";
  textoProgreso.textContent = pasosProgreso[paso].mensaje;
  paso++;
  if (paso === pasosProgreso.length) {
    clearInterval(intervalo); // la "tarea" ya terminó
    setTimeout(() => { /* muestra el modal de pago exitoso */ }, 400);
  }
}, 550);

Semana 14 · Promesas

Envolver un callback en una Promise

Simula la llamada a un servidor que calcula la agenda del médico. El resultado se entrega con resolve() en vez de un callback anidado a mano.

function obtenerAgendaMedico(idMedico) {
  return new Promise((resolve) => {

Semana 15 · JS Asíncrono: async/await

Esperar una promesa sin bloquear el navegador

await pausa esta función —no la página— hasta que la promesa se resuelve. El usuario puede seguir usando la app mientras "carga" la agenda.

document.getElementById("lista-medicos").addEventListener("click", async (e) => {
  // (...identifica el médico seleccionado)
  cargando.classList.remove("oculto");

  const dias = await obtenerAgendaMedico(medicoSeleccionado.id);

  cargando.classList.add("oculto");
  contenedorDias.innerHTML = dias.map(dibujarDiaAgenda).join("");
});
